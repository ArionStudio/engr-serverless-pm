# Work item 20 contract/source-of-truth inventory

Date: 2026-08-16

Baseline: `e6f08e16`

This append-only inventory is the Finding 28 research slice. It accounts for
the current exported commands/results, services, multi-state domain helpers,
nested contexts, repeated identities, secret/visible views, and production
callers. It recommends follow-up ownership changes but intentionally changes no
production signature.

## Scope accounting

The inventory starts at `packages/core/package.json`,
`packages/core/src/index.ts`, and
`packages/core/src/use-cases/index.ts` rather than at file-name guesses.
The current surface contains:

- 33 exported use-case classes;
- 31 named command aliases (list-vaults and session-status take no command);
- 23 named result aliases, two domain-type results, two inferred/inline object
  results, and six `void` results;
- ten service classes with 46 public asynchronous methods and one public
  synchronous validation method;
- 49 production domain functions exported from their declaring modules,
  including 17 with three or more related state parameters; package-root
  reachability is determined separately through the domain barrels and recorded
  for signature-change candidates; and
- one narrow production composition root for clipboard-alarm handling; the
  extension also maintains a compile-time composition fixture, but still has no
  complete vault/sync application composition root.

The package root exports domain, errors, ports, and use cases. Services are
available through the explicit `@lfspm/core/services` subpath
(`packages/core/package.json`, `packages/core/src/services/index.ts`), not
through the root barrel. Finding 16's service-export prerequisite is therefore
already resolved on this baseline; construction control remains a separate
Finding 16 concern.
